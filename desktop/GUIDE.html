CareerOps Desktop

使用指南

從第一次啟動到匯入背景證據、分析職缺、找工作、追蹤申請與準備面試。一般使用不需要自己操作 Markdown、YAML 或 coding-agent prompt。

目前版本範圍：這份指南只描述 tauri-dashboard 已有的功能。尚未合併的 release、自動更新、Homebrew 與 Windows 發佈流程不列入本指南。

1. CareerOps Desktop 是什麼

CareerOps Desktop 是建立在 CareerOps 核心上的原生桌面介面。Desktop 負責 UX 與流程編排；CareerOps 上游仍負責 tracker、report、scanner、batch、文件產生與其他 domain logic。

Desktop UI → AgentRunner / Tauri → AI Provider → CareerOps Core → Canonical files
Desktop 負責

讓流程可以直接操作

Onboarding、Home、Evaluate、Scanner、Jobs、Interview、Progress、Profile 與 Help 都可從 App 進入。

CareerOps Core 負責

維持真正的求職邏輯

評估、tracker、狀態、報告、職缺掃描、batch 與文件格式仍以上游為準，Desktop 不另外複製一套規則。

Human in the loop：AI 可以分析、起草與建議，但不會替你直接送出申請或寄出 outreach。最後決定仍由你控制。

2. 第一次啟動

第一次開啟 App 時，先建立或選擇 CareerOps workspace。這是你的私人資料夾，和已安裝的 App、App 的技術狀態，以及審閱後的 profile 是不同的概念。

Workspace

你的求職資料放在這裡

macOS 預設是 ~/Documents/CareerOps；Windows 預設是 Documents\CareerOps。也可以改用自訂位置或既有 CareerOps workspace。

App 與 profile

不要把三者混在一起

App 安裝與其受管理 runtime 是技術狀態；背景檔案是證據；審閱後寫入 canonical files 的內容才是你的 profile。

建立或選擇 workspace

可以直接建立預設位置，或選擇自訂位置。App 會記住目前使用的 workspace。

Welcome

開始 onboarding；也可以先跳過文件匯入，之後再補。

Import your background

拖放檔案、確認分類，並在之後審閱 CareerOps 根據這些證據提出的 profile 更新。

選擇 Analysis Language

決定你閱讀 Dashboard 與分析報告時使用的語言。

Set up AI

App 偵測本機已安裝並可使用的 AI CLI，選一個作為預設 Provider。

Ready

進入 Home，開始分析單一職缺或掃描符合條件的工作。

3. 匯入背景資料

Background Import 會把你的職涯資料當作證據處理，而不是建立多個彼此獨立的 profile database。這些證據會一起供單一 intake 審閱使用。

八個分類

檔案送到正確位置

  • CV / Resume
  • Work records
  • Publications / Research
  • Degrees / Transcripts
  • LinkedIn
  • References
  • Certificates
  • Portfolio / Projects
Canonical profile

最後只有三個權威輸出

審閱後的 profile 寫入 cv.md、config/profile.yml 與 modes/_profile.md。其他匯入檔是 supporting evidence，不是第二套 profile。

Drag / Add files → Review category → Copy to documents/<category>/ → One intake review → Explicit apply

拖放檔案或按 Add files 後，請檢查每個檔案的 category。App 會把選取檔案複製到 workspace 的 documents/<category>/。AI setup 完成後，CareerOps 會在一個整合 intake 中檢查所有新增或變更過的證據，並提出附來源的 profile 更新建議。

你會先看到每個 proposal、目標檔案、來源與可能的衝突。沒有任何 canonical profile 檔案會在預覽時被改寫；只有你勾選的 proposal 會在按下 Apply selected changes 後套用。

PDF 限制：此 build 仍會 stage PDF，但不能抽取其中的文字。若要讓內容參與 profile extraction，請同時加入對應的 .md、.txt 或 .tex 檔。

目前 macOS release 支援審閱式 AI intake。Windows 與 self-contained Linux package 若沒有可用的安全 provider isolation，審閱式 intake 階段會 fail closed：已 stage 的證據維持不變，canonical profile 檔案不會被修改；更新到支援的 package 後再試。

4. Analysis Language 與 Job Language

CareerOps Desktop 不再用同一個語言設定控制所有輸出。你閱讀分析的語言，和每份職缺實際使用的文件語言，是兩件不同的事。

Analysis Language

你用什麼語言閱讀 Dashboard 與 report。可在 onboarding 或 Profile → Job Search 中修改。

≠
Job Language

每個職缺各自從 JD 判斷。CV、cover letter 與 interview material 跟著這個語言。

例子：Analysis Language 選繁體中文，貼入德文 JD → 分析內容可以是繁中，但 CV、cover letter 與面試材料仍使用德文。

Job Language 怎麼決定？

CareerOps 會優先使用你對該職缺的手動 override；沒有 override 時，再從 JD 或可靠的職缺內容判斷。若信心偏低，Evaluate 畫面會顯示偵測結果與 [Change]，讓你直接改。

Market mode 是第三件事。它處理市場詞彙與地方規則，不等於 Analysis Language，也不等於 Job Language。

5. 選擇 AI Provider

CareerOps Desktop 透過本機 AI CLI 執行需要 reasoning 的工作，不需要另外設定一個 localhost port。你可以在 onboarding 選 Provider，也可以之後到 Profile → AI 切換。

Ready Not installed Not authenticated Error
想用 Codex

先讓 Codex 本機可用

如果 App 偵測到 Codex 為 Ready，直接選它即可。選擇會保存成 preferred provider。

Provider 切換

不用重跑 onboarding

之後可在 Profile → AI 選其他已 Ready 的 Provider。AgentRunner 會使用目前偏好的 Provider。

如果 Provider 顯示 Not authenticated 或 Error，先回到該 CLI 自己的登入／驗證流程處理，再重新開啟或重新偵測。

6. Home：從這裡開始

Home 是日常入口。上方會顯示 tracked、interviewing、applied 與平均分數；主要有兩條工作流。

Evaluate a job

已經有一個職缺

貼上職缺 URL 或 JD 文字，進入單一職缺分析。

Find matching jobs

讓 CareerOps 幫你找

從設定好的來源執行 Scanner，找出符合條件的新機會。

Home 下方也會顯示最近活動，方便快速回到 Jobs 查看申請。

7. 分析單一職缺

在 Home 貼上職缺 URL 或 JD 後，Evaluate 會透過 AgentRunner 執行 CareerOps 的評估流程。

Read posting → Match background → Role requirements → Compensation → Evaluation

開始前可以調整文件語言

預設讓 CareerOps 從 JD 判斷。若你已經知道應該使用哪個語言，可以直接在 Document language 手動指定。

Agent Activity

執行期間會顯示階段、輸出與錯誤資訊。你可以 Cancel；失敗後可以 Retry。完成後回到 Jobs 查看結果與 report。

8. 找符合條件的職缺

Scanner 會讀取已設定的求職來源，先找新職缺，再去重複、預篩，最後評估符合條件的候選工作。

Scanning sources → Deduplicating → Pre-screening → Evaluating matches

掃描完成後按 View results 回到 Jobs。CareerOps 的 scanner / batch domain logic 仍由核心處理，Desktop 主要負責啟動、顯示進度與結果。

9. Jobs：管理申請

Jobs 是原本 Pipeline 的產品化介面。你可以篩選、排序、搜尋、切換檢視方式、閱讀 report，並更新申請狀態。

Grouped / Kanban

按狀態整理

以 board 方式瀏覽申請。點選項目時，report 會在 drawer 中顯示。

Table / Split

快速比較

用表格排序與搜尋，選取後可在旁邊閱讀 report。

狀態修改有保護

Desktop 不會直接任意重寫 tracker。它使用目前讀到的狀態作 optimistic lock；如果檔案已被別的流程改過，會拒絕 stale write，要求 Reload。

狀態選項來自 CareerOps 的 canonical contracts，不要把某一組固定狀態視為 Desktop 自己的硬編碼規則。

10. Interview：準備、練習、複盤

Jobs 中狀態為 Interview 的申請會自動出現在 Interview 頁。每一個 active interview 都有三種工作流。

Prep plan

準備計畫

讀取職缺情境，建立面試準備計畫與時間安排。

Practice

模擬練習

準備面試題目與練習材料，透過 AgentRunner 執行。

Debrief

面試後複盤

整理面試筆記、找出缺口，並讓 CareerOps 更新可重用的知識資料。

Interview 畫面也可以設定 Interview language。Practice、planning 與 debrief material 使用 Job Language；Analysis Language 仍維持你選擇的閱讀語言。

11. Progress 與 Profile

Progress

看求職漏斗

用 CareerOps 已有資料查看追蹤數量、各狀態分布與進度統計，不另外建立 Desktop-only database。

Profile

調整你的設定

Profile & Settings 分成 My Background、Job Search、Search Sources、AI 四個區域。

Profile 區域 用途
My Background 查看背景證據與審閱後的 profile；進階使用者可直接檢查 cv.md、config/profile.yml 與 modes/_profile.md。
Job Search 目標職位、地點、remote、薪資等偏好，以及 Analysis Language。
Search Sources CareerOps 要掃描的公司與 job board，對應 portals.yml。
AI 查看 Provider 狀態並切換 preferred AI Provider。

Workspace

Settings 的 Workspace 區塊會顯示目前路徑，並提供 Open Folder 與 Change Location。Open Folder 會在檔案管理器開啟目前 workspace；Change Location 只會切換 active workspace，不會搬移之前的 workspace 或其中檔案。

App 技術狀態：打包 App 已包含受管理的 JavaScript runtime 與必要 assets。一般使用不需要安裝 Git、Homebrew、Node、npm、Rust 或 Go。若 package assets 或 runtime 缺失，請重新安裝或更新 CareerOps Desktop，而不是執行 developer repair commands。

12. Help 與疑難排解

Help 頁提供 scores、scanner、AI 能做什麼／不能做什麼、privacy、troubleshooting 與 advanced 等快速說明，也可以載入完整 README 文件。

常見問題

我需要一直開 Codex / Claude 的 Terminal 嗎？

一般 Desktop 工作流不需要你手動留在 coding-agent session 裡操作。App 透過 AgentRunner 呼叫你已設定好的本機 Provider。

我想固定使用 Codex，要改 port 嗎？

不用。這個架構使用本機 CLI provider，不是連 localhost HTTP server。只要 Codex 被偵測為 Ready，於 onboarding 或 Profile → AI 選 Codex 即可。

為什麼職缺語言和分析語言不同？

這是刻意設計。Analysis Language 是你閱讀分析的語言；Job Language 是該職缺的工作文件語言。兩者分開，才能例如用繁中看分析、同時產生德文履歷。

掃描或分析卡住怎麼辦？

先看 Agent Activity 的目前階段與 Technical output。可以 Cancel 後 Retry。若 Provider 是 Error / Not authenticated，先處理 Provider 本身；若 App 指出 package assets、managed runtime 或 data service 缺失，請重新安裝或更新 CareerOps Desktop。

Background Import 完成後，AI 已經改寫我的 profile 了嗎？

還沒有。匯入會先把你分類過的檔案複製到 documents/<category>/，再在一個 intake 中產生建議。只有你明確核准的個別 proposal 會在你按下 Apply selected changes 後寫入 cv.md、config/profile.yml 或 modes/_profile.md。

資料會傳到 CareerOps 的雲端嗎？

CareerOps Desktop 本身不是 hosted backend。資料主要保存在本機 CareerOps files；需要 AI 分析時，實際傳送範圍與處理由你選擇的 AI Provider 決定。

本指南尚未包含：App 內自動更新、GitHub Release 安裝、Homebrew、Windows installer 與 biweekly upstream maintenance。這些屬於尚未 merge 進 tauri-dashboard 的 feature/fork-release-system。
